# 设计模式面试题

## Q1. 常见设计模式概览

共 23 种设计模式，常见有：单例模式、工厂模式、代理模式、适配器模式、模板方法模式

**在 Spring 中的体现：**
| 设计模式 | Spring 中的体现 |
|---------|---------------|
| 单例模式 | Spring 中的 Bean 默认就是单例模式 |
| 工厂模式 | Spring 中的 BeanFactory |
| 代理模式 | AOP（面向切面编程）底层使用动态代理实现 |
| 适配器模式 | SpringMVC 根据处理器规则适配处理器 |
| 模板方法模式 | MyBatis 中的 JdbcTemplate 使用了模板方法模式 |

## Q2.**单例模式（Singleton）**

保证一个类只有一个实例。最常用的场景是配置管理、日志系统、数据库连接池——这些东西全局只需要一份。

```java
public class Config {
    private static Config instance;
    private Config() {}
    public static Config getInstance() {
        if (instance == null) instance = new Config();
        return instance;
    }
}
```

**代理模式（Proxy）**

为目标对象套一层"壳"，在不修改原有代码的情况下增加额外逻辑。Spring AOP 就是典型应用——你写了一个 `UserService`，Spring 自动生成一个代理类，在调用方法前后插入事务、日志等逻辑，你的业务代码完全不用改。

**JDK 动态代理 vs CGLIB**

JDK 动态代理基于**接口**，目标类必须实现接口，代理类和目标类是"兄弟关系"（共同实现同一接口）。

CGLIB 基于**继承**，通过生成目标类的子类来代理，不需要接口，但不能代理 `final` 类和 `final` 方法。

Spring 的选择策略：目标类有接口 → JDK 动态代理；没有接口 → CGLIB。Spring Boot 2.x 之后默认全部用 CGLIB。

**模板方法模式（Template Method）**

父类定好流程骨架，子类填充具体步骤。比如泡饮料：烧水 → 冲泡 → 倒入杯子 → 加配料，前三步一样，最后一步泡茶加柠檬、泡咖啡加牛奶，父类把流程写死，子类只实现"加配料"这一步。`JdbcTemplate` 就是这个思路，连接、执行、关闭由框架管，你只写 SQL。

---

**策略模式（Strategy）**

把可变的行为抽成接口，运行时动态切换。最直观的例子是电商促销：满减、打折、赠券是三个不同策略，结算时根据活动类型选对应策略执行，不用堆 if-else，新增促销方式也不用改老代码。

```java
interface DiscountStrategy { double calc(double price); }
class Discount90 implements DiscountStrategy { ... }
class FullMinus implements DiscountStrategy { ... }
```
