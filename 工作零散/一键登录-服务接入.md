一键登录的本质是 **运营商帮你确认用户的本机手机号**，SDK 只负责传递 “临时凭证”，后端只需要用这个凭证换手机号，最终存储**用户手机号（或加密后的手机号）** 完成登录 / 注册。

---

### 一、 底层核心：SDK 到底获取了什么信息？

SDK **不会直接获取手机号**，而是获取一个和手机号**一一绑定的临时凭证（Token）**，整个过程分 2 步：

1. **运营商****网关****的 “身份识别”**当用户手机开着移动数据（4G/5G）时，手机会和运营商网关建立连接，网关里存着 3 个关键绑定关系：
    
    1. 手机 SIM 卡的 **IMSI** **码**（和手机号是唯一对应关系，相当于手机号的 “隐形身份证”）；
        
    2. 手机的 **IMEI** **码**（设备唯一标识）；
        
    3. 当前网络的基站信息。运营商通过这 3 个信息，能 100% 确定：**这台设备正在用的手机号是 XXX**。
        
2. **SDK 的 “凭证获取”**用户点击 “一键登录” 并授权后，SDK 会做两件事：
    
    1. 向运营商网关发送请求：“请给我一个能证明这个设备手机号的临时凭证”；
        
    2. 运营商网关生成一个 **短期、一次性的 Token**（有效期通常 1-5 分钟），这个 Token 和用户手机号是绑定的，但**Token 本身不带任何手机号****明文**；
        
    3. SDK 把这个 Token 返回给你的 App 客户端。
        
3. 👉 **关键结论**：SDK 获取的是 **“能证明手机号的 Token”**，不是手机号本身，避免了隐私泄露。
    

---

### 二、 验证逻辑：从 “用户点击” 到 “登录成功” 的完整链路

整个验证逻辑是 **“客户端→SDK→运营商→服务端”** 的三方协同，分 5 步走，没有任何一步会直接传递明文手机号：

1. **用户触发**：用户在 App 上点击 “一键登录”，同意隐私协议。
    
2. **SDK 请求 Token**：客户端调用 SDK 接口，SDK 向运营商网关发起 Token 申请（依赖移动数据网络）。
    
3. **运营商生成 Token**：运营商验证设备 IMSI+IMEI 的绑定关系，确认手机号，生成临时 Token，返回给 SDK。
    
4. **客户端传 Token 给后端**：客户端把 Token 传给你的后端服务器（全程 HTTPS 加密）。
    
5. **后端核验 Token 换手机号**：
    
    1. 后端拿着 Token + 自己在服务商申请的 `appKey/appSecret`（身份凭证），调用第三方服务商的**REST API**；
        
    2. 服务商验证 Token 有效性（是否过期、是否被篡改），验证通过后，返回对应的**手机号**给后端；
        
    3. 后端拿到手机号后，判断这个手机号是否在自己的用户数据库里：
        
        - **已存在**：生成登录凭证（如 JWT Token），返回给客户端，登录成功；
            
        - **不存在**：自动创建账号（用手机号作为唯一标识），再生成登录凭证，完成注册 + 登录。
            

👉 **关键验证点**：

- 运营商验证 **“设备和手机号的绑定关系”**；
    
- 服务商验证 **“Token 的有效性”**；
    
- 你的后端验证 **“手机号是否属于自己的用户”**。
